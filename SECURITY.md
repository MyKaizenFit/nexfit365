# Security Policy

## Supported versions

Security fixes are applied to the latest code on `main` of [NexFit365](https://github.com/MyKaizenFit/nexfit365). Older tags or forks are not routinely patched.

## Reporting a vulnerability

**Do not** open a public GitHub issue for security problems (RCE, auth bypass, data exposure, injection, etc.).

Prefer one of these private channels:

1. **[GitHub Security Advisories](https://github.com/MyKaizenFit/nexfit365/security/advisories/new)** — private report to maintainers (preferred).
2. If you cannot use Advisories, contact a repository maintainer directly and mark the message as a security report.

Please include:

- Affected component (frontend / backend / deploy / docs)
- Steps to reproduce or a proof of concept
- Impact assessment (who can exploit it, what data is at risk)
- Any suggested fix, if you have one

## Response targets

We aim to:

- Acknowledge receipt within **7 days**
- Share an initial triage (accepted / needs more info / declined) within **14 days**
- Coordinate disclosure after a fix is available, or agree on a timeline if the issue is deferred

These are best-effort targets for a small maintainer team, not SLAs.

## Safe harbor

Good-faith research that follows this policy and avoids privacy violations, service disruption, or data destruction is welcome. Do not access other users’ data beyond what is needed to demonstrate the issue.
